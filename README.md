# Plexmate Guard

FlaskFarm용 Plexmate Guard 플러그인입니다. Plex 메타데이터 큐, SJVA agent 대기, Plex Scanner, Plexmate 작업 수와 NAS 부하를 한 화면에서 관찰하고, 사용자가 Plexmate 신규 스캔을 `2 → 1 → 0`으로 안전하게 제어할 수 있게 합니다.

## 0.2.0 안전 범위

- Plex 또는 FF를 자동 재시작하지 않습니다.
- 기존 FF Command watchdog을 수정하거나 켜지 않습니다.
- `0`은 진행 중인 스캔을 종료하지 않으며 이후 신규 Plexmate 스캔 시작만 막습니다.
- 대시보드의 **Plex 수동 재시작**은 Plexmate 제한이 실제 `0`이고, 네이티브 또는 명시한 Docker Plex 대상이 확인된 경우에만 활성화됩니다.
- 수동 재시작은 두 번의 사용자 확인 뒤 한 번만 요청하며, 실패·시간 초과 시 자동 재시도하지 않습니다.
- Plex 데이터베이스 마이그레이션 응답(503)은 수동 재시작도 차단합니다.
- 기본으로 켜진 **상세 운영 로그**는 조회·관찰마다 HTTP 응답시간, 큐 변화, SJVA 최대 대기, 최근 timeout, Plexmate 작업 수·제한, 설치 방식과 NAS 부하를 기록합니다. 토큰·원본 Plex 로그·개별 파일 경로는 기록하지 않습니다.
- 개별 metadata 갱신은 상태 조회와 분리된 30초 제한 시간을 사용합니다. 그 안에 응답하지 않으면 Plex가 계속 처리 중일 수 있으므로 해당 후보의 즉시 중복 요청을 막고 확인을 안내합니다.
- **대기 전체 갱신 시작**은 Plexmate 제한이 `0`이고 Plex가 `NORMAL`일 때만 실행됩니다. 한 항목씩 설정한 간격으로 요청하며, 각 요청 뒤 Plex가 잠시 `BUSY`이면 다음 요청을 보내지 않고 최대 5분간 안정화를 기다립니다. Plex에서 이미 사라진 ratingKey의 `HTTP 404`는 해당 Guard 후보만 이력 보관하고 다음 항목을 계속 처리합니다. 정체·마이그레이션·통신 장애·그 밖의 요청 오류일 때만 중지합니다.
- 요청 완료 항목은 삭제하지 않고 `요청 완료 이력 보관`으로 화면에서 숨긴 뒤 이력으로 확인할 수 있습니다.
- `Guard 사용`, `자동 관찰 실행`, `상세 운영 로그` 스위치는 바꾸는 즉시 저장됩니다. FF/플러그인 재시작과 Git 업데이트 뒤에도 이 값은 Guard DB에서 유지됩니다.
- **안전 브레이크 자동 0 전환**은 기본 OFF입니다. 켠 경우에만 스케줄 관찰에서 `METADATA_BLOCKED`가 연속 2회 또는 `PLEX_UNAVAILABLE`가 연속 3회 확인될 때 Plexmate 신규 스캔 제한을 `0`으로 전환합니다. 단순 BUSY·마이그레이션·대시보드 새로고침은 카운트하지 않습니다. 정상 상태가 연속 3회 확인되면 회복 상태로 전환합니다. 0.7.0부터 별도의 `안정화 후 자동 재개` 옵션을 켠 경우에만 단계적 자동 재개를 수행하며, Plex 자체 자동 재시작은 하지 않습니다.

- Plexmate 로그의 database is locked는 기본 /data/log/plex_mate.log에서 별도로 집계합니다. 기본 기준은 최근 10분 3회 또는 60초 안 3회이며, 한 번의 잠김은 관찰만 하고 PLEXMATE_DB_LOCKED로 오판하지 않습니다.
- PLEXMATE_DB_LOCKED가 스케줄에서 2회 연속 확인되고 안전 브레이크가 켜져 있으면 Plexmate 실행 제한을 0으로 낮춥니다. 진행 중인 스캔을 강제 종료하거나 Plex를 자동 재시작하지 않습니다.
- 실행 제한 0은 Plexmate 스캔 워커를 멈추는 방어선입니다. 외부 do_scan 요청 자체를 차단하는 기능은 아니므로, 잠김 폭주가 계속되면 대시보드에서 유입원과 scan_item 대기량을 함께 확인해야 합니다.
## 설치

FF의 **시스템 → 플러그인 → 로딩 플러그인**에서 아래 URL을 설치합니다.

```
https://github.com/iamnosik/plexmate_guard
```

설치 뒤 **Plexmate Guard → 설정**에서 로그 경로와 관찰 기준을 확인하고, 먼저 `Guard 사용`을 켠 뒤 관찰 모드로 사용하세요.

## 롤백

Guard를 끄고 대시보드에서 `기본값 복원`을 누르면 Plexmate 실행 제한을 저장된 기본값으로 되돌립니다. Guard DB와 기존 Plexmate/Plex 데이터는 삭제하지 않습니다.

## 0.6.2 판단 이력 저장 최적화

- 대시보드 새로고침과 metadata 사전 점검은 상태를 조회만 하며 `guard_event` 이력을 만들지 않습니다.
- 스케줄 관찰의 `NORMAL`/`BUSY`는 상태가 바뀌는 순간과 기본 60분 heartbeat만 대표 이력으로 보존합니다.
- `METADATA_BLOCKED`, `PLEX_UNAVAILABLE`, `PLEXMATE_DB_LOCKED`, `MIGRATION`은 연속 판정 근거 확인을 위해 스케줄마다 계속 기록합니다.
- 과거 반복 `NORMAL` 이력은 1시간당 대표 1건으로 압축하고 보존 기간(기본 30일)을 넘긴 반복 샘플은 정리합니다. 장애에서 `NORMAL`로 복귀한 상태 전환 이력은 기간과 무관하게 보존합니다.
- 이력 압축은 하루 한 번 이하로 수행하며 장애·수동 제어·metadata 재시도·Safety Brake 이력은 정리 대상이 아닙니다.
- 자동 Safety Brake가 제한을 `0`으로 낮출 때 동일 동작이 이력에 두 번 기록되던 중복을 제거했습니다.

## 0.6.3 SQLite 이력 정리 안정화

- 대규모 과거 NORMAL 이력 최초 압축 시 한 트랜잭션으로 오래 잠그지 않도록 200건씩 삭제·commit합니다.
- 각 배치 실패 시 rollback하며, Guard 판단 및 Safety Brake 로직에는 영향을 주지 않습니다.

## 0.7.0 단계적 자동 재개

0.7.0에서는 안전 브레이크가 Plexmate 신규 스캔 제한을 0으로 낮춘 뒤 Plex가 회복되었을 때, 사용자가 선택한 경우에만 단계적으로 자동 재개할 수 있습니다.

- 자동 재개 기본값은 OFF입니다. 기존 동작을 바꾸지 않으며 설정에서 '안정화 후 자동 재개'를 직접 켠 경우에만 동작합니다.
- Guard가 직접 안전 브레이크를 건 경우에만 자동 재개할 수 있습니다. 사용자가 직접 0으로 멈춘 상태는 Guard가 임의로 다시 켜지 않습니다.
- 자동 브레이크 순간의 실제 scan_max_scan_count를 '정지 전 실행 수'로 저장합니다. FF 또는 Guard가 재시작되어도 상태와 타임스탬프는 설정 DB에 유지됩니다.
- 기존 회복 조건인 연속 NORMAL 확인을 통과한 뒤에도 바로 재개하지 않고 기본 10분의 추가 안정화 시간을 둡니다.
- 추가 안정화 중에는 Plex identity, library 응답, Plexmate DB 잠김, SCANNING 작업, NAS의 디스크 대기(D-state) 프로세스 수를 함께 확인합니다.
- 안정화 조건을 통과하면 먼저 실행 제한 1로 시험 재개합니다.
- 시험 재개는 기본 15분 동안 감시하며 NORMAL과 정상적인 BUSY는 허용합니다.
- 시험 중 PLEX_UNAVAILABLE, METADATA_BLOCKED, PLEXMATE_DB_LOCKED, Plex migration, API 실패, DB 잠김 또는 과도한 D-state가 나타나면 즉시 다시 0으로 내리고 수동 확인 필요 상태로 바꿉니다.
- 시험 재개가 끝까지 안정적이면 정지 전에 저장한 실행 수로 복원합니다. 정지 전 값이 1이었다면 그대로 1을 유지한 채 자동 회복을 완료합니다.
- 자동 재개 후 기본 30분 안에 다시 안전 브레이크가 걸리면 반복 재개하지 않고 수동 확인을 요구합니다.
- 브레이크 또는 자동 재개 중 사용자가 Guard 대시보드나 Plexmate 설정에서 실행 제한을 직접 바꾸면 사용자 조작이 항상 우선합니다. Guard는 현재 값을 변경하지 않고 자동 제어권만 해제합니다.
- 자동 재개 옵션을 시험 재개 도중 OFF로 바꿔도 현재 실행 제한은 그대로 두고 자동 제어만 중단합니다.
- Plex Server 자체의 자동 재시작은 여전히 하지 않습니다. Plex 재시작은 기존과 같이 사용자 확인 방식만 유지합니다.

권장 기본값:

| 항목 | 기본값 | 의미 |
| --- | ---: | --- |
| 회복 정상 연속 확인 | 3회 | 기존 회복 판정 |
| 자동 재개 전 추가 안정화 | 10분 | 실행 제한 0 상태에서 추가 관찰 |
| 1개 시험 재개 감시 | 15분 | 실행 제한 1로 안전성 확인 |
| 자동 재개 후 재발 차단 | 30분 | 짧은 시간 내 재정지 시 수동 전환 |
| 허용 D-state 최대 수 | 3개 | 과도한 디스크 대기 시 재개 연기 |

상태 흐름:

    NORMAL
      -> 연속 장애
    SAFETY_BRAKE (실행 제한 0)
      -> 연속 NORMAL
    RECOVERY_READY
      -> 추가 안정화
    STABILIZING
      -> 실행 제한 1
    PROBE
      -> 안정 감시 통과
    정지 전 실행 수 복원
      -> RECOVERED

    PROBE 중 위험 재발
      -> 즉시 0
      -> MANUAL_REQUIRED
